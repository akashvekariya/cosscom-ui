## Installation

```bash
npx shadcn@latest add @coss/flow
```

Flow is plain markup: a column of cards, lines and one bracket. There is no canvas library, no pan or zoom, and nothing is positioned or measured in script.

## Usage

```tsx
import { BellIcon, SplitIcon, ZapIcon } from "lucide-react"
import {
  Flow,
  FlowBranch,
  FlowConnector,
  FlowEnd,
  FlowPath,
  FlowStep,
} from "@/components/ui/flow"

export function Workflow() {
  return (
    <Flow aria-label="Start onboarding for won deals">
      <FlowStep
        icon={<ZapIcon />}
        kind="Starts when"
        title="A deal moves to Won"
        tone="trigger"
      />
      <FlowConnector />
      <FlowStep icon={<SplitIcon />} kind="Check" title="Is the kickoff date set?" />
      <FlowConnector size={16} />
      <FlowBranch label="Is the kickoff date set?">
        <FlowPath label="Yes">
          <FlowConnector size={16} />
          <FlowEnd>Done</FlowEnd>
        </FlowPath>
        <FlowPath label="No">
          <FlowConnector size={16} />
          <FlowStep icon={<BellIcon />} kind="Notify" title="Notify the deal owner" />
        </FlowPath>
      </FlowBranch>
    </Flow>
  )
}
```

The parts are placed in reading order, top to bottom. Put a `FlowConnector` (or a `FlowAdd`) between any two things that should be joined by a line. Each line ends in a small arrowhead where it reaches the next step, so the direction is always clear; lines into a branch end at its bracket instead. Set `arrows={false}` on `Flow` for plain lines.

### Parts

| Part | Draws |
|------|-------|
| `Flow` | The dotted surface. Centers one column and scrolls when the flow is wider or taller than its frame |
| `FlowStep` | One card: an icon tile, the kind of step, a plain sentence and an optional status chip |
| `FlowConnector` | The line between two things: 22px, or 16px around a branch, or 8px |
| `FlowAdd` | A round plus button on the line, with a tooltip |
| `FlowBranch` | The bracket under a check, holding its paths side by side |
| `FlowPath` | One path of a branch: a pill label, then its own steps |
| `FlowEnd` | The muted pill that ends a path |
| `FlowGroup` | A framed set of steps with a header: a loop, or a group that folds away |
| `FlowJump` | A pill that ends a path by going back to an earlier step |
| `FlowChip` | The status pill, for building your own status content |

### Steps

```tsx
<FlowStep
  icon={<ClockIcon />}
  kind="Wait"
  title="Wait 2 days"
  status={{ label: "12 waiting", tone: "waiting" }}
/>
```

- `kind` names the step in a few words ("Starts when", "Wait", "Check"); it stays on one line.
- `title` is a plain sentence; it wraps to two lines.
- `tone="trigger"` tints the icon tile. Color appears only there and on status.
- `status` is usually a number and a word, such as "128 runs" or "3 failed". Tones are `neutral`, `running`, `waiting`, `failed` and `done`.
- `muted` dims a step, for example one that no run has reached.
- Pass `onClick` and the card becomes a button; `selected` draws a ring around it.

Cards are 300px wide at the top level and 260px inside a path, and shrink on narrow screens.

### Branches

A branch follows its check with a 16px line. Each path starts with its label, a 16px line, then its steps. A path is at least as wide as a step and grows with its content, and each path draws its own half of the bracket, so the bracket fits paths of any width. A branch can sit inside a path; keep it to two levels. When the paths do not fit, the surface scrolls sideways.

### Joining paths

```tsx
<FlowBranch join label="Is it paid by card?">
  <FlowPath label="Yes">…</FlowPath>
  <FlowPath label="No">…</FlowPath>
</FlowBranch>
<FlowConnector size={16} />
<FlowStep … />
```

With `join`, each path runs a line down to a bracket under the branch, mirroring the one above, and the flow carries on below it. A path that ends with `FlowEnd` or `FlowJump` stays out of the join.

### Loops

Two shapes, both top to bottom, with no line drawn back up the page:

- **Repeat a set of steps:** put them in a `FlowGroup` whose header says what repeats, such as "Repeat: For each item in the order".
- **Go back and try again:** end a path with `<FlowJump>Back to Charge the card</FlowJump>`. Say the limit in a status, such as "Up to 3 times".

### Groups

```tsx
<FlowGroup
  collapsible
  defaultOpen={false}
  icon={<LayersIcon />}
  kind="Group"
  title="Set up their accounts"
  status={{ label: "3 steps" }}
>
  <FlowConnector size={16} />
  <FlowStep … />
</FlowGroup>
```

A group frames its steps under a header that looks like a step. Steps inside are 40px narrower than the group. With `collapsible`, the header becomes a button that folds the group down to a single card, which keeps long workflows short. `open` and `onOpenChange` control it.

### Narrow frames

When the frame is narrower than 38rem (608px), the paths stack: each label becomes a small heading with its steps indented under it. The same markup serves both layouts; the switch is a container query on `Flow`, so it follows the space the flow has, not the window.

### Editing

```tsx
<Flow editable={editing}>
  <FlowStep … />
  <FlowAdd onClick={() => addStep(1)} />
  <FlowStep … />
  <FlowAdd size={16} onClick={() => addStep(2)} />
  <FlowBranch …>…</FlowBranch>
</Flow>
```

Write the flow once with `FlowAdd` on every line. While `editable` is true each one shows a plus button; when it is false the same markup draws plain lines. `size` on `FlowAdd` is the line it stands in for: 22 between steps, 16 into a branch and under a path label.

### Custom content

Every part of a step takes any content, so the card can show whatever your workflow needs:

```tsx
<FlowStep
  icon={<img alt="" src="/logos/crm.svg" />}
  kind="Approve"
  title="A manager approves it"
  status={
    <>
      <FlowChip tone="done">212 done</FlowChip>
      <FlowChip tone="failed">2 failed</FlowChip>
    </>
  }
>
  <Badge size="sm" variant="outline">Over $500</Badge>
  Within 2 days
</FlowStep>
```

- `status` takes `{ label, tone }` for one chip, or any element instead: several chips, avatars, a switch, a time.
- Children appear under the title, for extra details such as tags, a recipient or a schedule.
- `icon` can be any element, including an app logo. `kind` is optional.
- `render` swaps the card element itself, for example to make it a link.
- What a settings panel shows is up to you; `FlowStep` only reports clicks and shows `selected`.

### Theming

Flow uses the theme tokens, so a theme recolors every flow:

| Token | Used for |
|-------|----------|
| `--muted` | Canvas, icon tiles and neutral chips |
| `--card`, `--border` | Cards and pills |
| `--info` | The trigger tile and `running` |
| `--warning` | `waiting`; also use it for a paused notice |
| `--destructive` | `failed` |
| `--success` | `done` |

Flow also reads three variables, set them on any parent or in your theme:

| Variable | Default | Sets |
|----------|---------|------|
| `--flow-line` | foreground at 40% | Lines, arrowheads and the bracket |
| `--flow-dot` | `--border` | The dot grid |
| `--flow-step-width` | `300px`, `260px` in paths | Card width |

For anything else, every part has a `data-slot`, and chips and steps have a `data-tone`, such as `[data-slot=flow-chip][data-tone=waiting]`.

### What it covers

| Workflow shape | How |
|----------------|-----|
| Trigger, actions, waits, checks | `FlowStep` with `tone="trigger"` for the first |
| Yes and No, or more paths | `FlowBranch` with one `FlowPath` each |
| Paths that join back into one line | `FlowBranch join` |
| Repeating steps, for each item or until done | `FlowGroup` with a "Repeat" header |
| Trying again from an earlier step | `FlowJump` at the end of a path |
| Folding a long section away | `FlowGroup collapsible` |
| Checks inside paths | A `FlowBranch` inside a `FlowPath`, up to two levels |
| Steps that run at the same time, error paths | A branch whose labels say so, such as "At the same time" or "If it fails" |
| Calling another workflow | A step |
| Runs, failures, skipped steps | `status` and `muted` |

Lines never run back up the page: loops are a framed group or a jump pill, so the flow always reads top to bottom.

### Notices

```tsx
<Flow notice={<Alert variant="warning">…</Alert>}>…</Flow>
```

`notice` sits above the first step, for example to say the workflow is paused.

## Accessibility

- The flow is an ordered list. Each branch is a group named by its `label`, with one list per path named by the path label.
- A step reads as its kind, then its title, then its status: "Wait: Wait 2 days, 12 waiting".
- Lines and the bracket are hidden from screen readers. Tab moves through clickable steps, group headers and add buttons in reading order.
- A group is its own list, named by its header. A collapsible header is a button that says whether it is open.
- Give `Flow` an `aria-label` that names the workflow.
- `muted` is visual only; say why in the title or status when it matters.
- Nothing animates for people who ask for reduced motion.

## API Reference

### Flow

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `arrows` | `boolean` | `true` | End each line with a small arrowhead |
| `dots` | `boolean` | `true` | Draw the dot grid |
| `editable` | `boolean` | `true` | Show the plus buttons of `FlowAdd` |
| `notice` | `ReactNode` | | Shown above the first step |
| `aria-label` | `string` | | Names the workflow list |
| `className` | `string` | | Classes on the frame; give it a height to scroll vertically |

### FlowStep

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `icon` | `ReactNode` | | Icon in the tile |
| `kind` | `ReactNode` | | The kind of step, on one line; optional |
| `title` | `ReactNode` | | A plain sentence, up to two lines |
| `tone` | `"default" \| "trigger"` | `"default"` | Tint the tile for the step that starts the flow |
| `status` | `{ label, tone? } \| ReactNode` | | A chip, or any content, at the right edge |
| `children` | `ReactNode` | | Extra details under the title |
| `selected` | `boolean` | `false` | Draw a ring |
| `muted` | `boolean` | `false` | Dim the step |
| `onClick` | `() => void` | | Makes the card a button |
| `render` | `ReactElement` | | Render the card as another element |

### FlowConnector

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `size` | `22 \| 16 \| 8` | `22` | Length of the line in pixels |

### FlowAdd

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `label` | `string` | `"Add a step"` | Button name and tooltip |
| `size` | `22 \| 16 \| 8` | `22` | The line it becomes when the flow is not editable |
| `onClick` | `() => void` | | Called when pressed |

### FlowBranch

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `label` | `string` | | The question the branch answers, usually the check's title |
| `join` | `boolean` | `false` | Join the paths back into one line below |

### FlowPath

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `label` | `ReactNode` | | Pill at the top of the path, such as "Yes" |

### FlowGroup

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `icon`, `kind`, `title`, `tone`, `status` | | | The header, as on `FlowStep` |
| `collapsible` | `boolean` | `false` | Make the header a button that folds the group |
| `open` | `boolean` | | Open state. Controlled |
| `defaultOpen` | `boolean` | `true` | Initial open state |
| `onOpenChange` | `(open) => void` | | Called when the group opens or closes |

### FlowJump

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `children` | `ReactNode` | | Where it goes, such as "Back to Charge the card" |
| `icon` | `ReactNode` | arrow up | Icon before the text |

### FlowChip

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `tone` | `"neutral" \| "running" \| "waiting" \| "failed" \| "done"` | `"neutral"` | Color of the pill |

### FlowEnd

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `children` | `ReactNode` | `"Done"` | Text in the pill |
